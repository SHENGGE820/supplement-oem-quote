# 保健代工線上詢價＋業管報價

B2B 保健食品代工的兩個網頁，用同一份資料格式串起來：

1. **客戶詢價頁**（`index.html`）：客戶依 BKE A 表的問法說明需求，送出後以 Email 通知業務。
2. **業管報價頁**（`quote.html`）：讀取那筆詢價，加上營養師的配方成本與包材、數量、毛利，產出對客報價單。

**線上試用：**
- 客戶詢價：https://shengge820.github.io/supplement-oem-quote/
- 業管報價：https://shengge820.github.io/supplement-oem-quote/quote.html

設計相關文件：[DESIGN.md](DESIGN.md)（設計語言）、[DESIGN-REVIEW.md](DESIGN-REVIEW.md)（設計審查紀錄）

## 工作情境

| 項目 | 說明 |
|---|---|
| 工作情境 | B2B 保健代工：客戶線上詢價 → 營養師配方成本 → 業管產出對客報價單 |
| 原本作業方式／痛點 | 客戶需求由業管口頭轉述填 A 表，常缺售價、每盒數量等資料而被營養師退回補件；報價時再人工比對包材、印刷階梯單價與數量，整理一份報價超過 40 分鐘 |
| 使用的 AI／自動化工具 | ChatGPT (Data Analysis) 整理計價邏輯、Excel 自動化邏輯，轉成網頁詢價單＋報價工作台 |
| 本次完成的功能 | 客戶自助填寫與 BKE A 表欄位一致的詢價單，關鍵欄位必填或明確標示「尚未確認」；業管讀入詢價並填入營養師成本後，自動帶入包材、建議三個數量方案、產出報價單與溝通重點 |
| 導入前後改善 | 詢價資料一次收齊、減少補件來回；報價整理時間從 40 分鐘縮短至約 3 分鐘 |

## 流程

```
客戶詢價頁 ──送出──▶ Email 給業務（含 A 表匯入資料 JSON）
                        │
                        ▼
                 （之後）BKE 建立 A 表案件 → 營養師填配方號碼、原料成本、加工費
                        │
                        ▼
業管報價頁 ◀──讀取詢價＋營養師成本── 包材／數量／毛利 ──▶ 報價單、BKE 報價資料 JSON
```

- 同一台電腦示範時，詢價頁送出的資料會直接出現在報價頁的「選擇詢價」清單。
- 跨電腦時，把詢價信裡「BKE A 表匯入資料（JSON）」整段貼到報價頁的「貼上 Email 裡的詢價資料」即可。

## 資料格式（接 BKE 時看這裡）

欄位定義集中在 [`bke-a-form.js`](bke-a-form.js)，選項文字與 BKE 的 `static/wizard.html`、`static/shared-case-store.js` 一字不差。**BKE 的 A 表選項有改時，請同步更新這個檔案。**

**詢價（`oem-inquiry/1`）**

```json
{
  "schema": "oem-inquiry/1",
  "inquiryNo": "RFQ-20261007-153012",
  "submittedAt": "2026-10-07T07:30:12.000Z",
  "contact": { "公司": "", "聯絡人": "", "電話": "", "Email": "", "預計上市": "", "銷售通路": "" },
  "summary": { "客戶名稱": "", "產品名稱": "", "產品類別": "👤 人營養補充品", "族群": [], "族群年齡": [], "調理部位": [], "期望功能": [], "客戶需求": "", "目標劑型": "💊 膠囊", "膠囊號數": "0 號", "目標成本": "3", "產品售價": "990", "產品每盒數量": "60", "產品每盒單位": "顆／盒", "成本備註": "", "包材備註": "", "配方方式": "全營養師開發", "特殊需求": [] },
  "extra": { "預計訂購量": "3000", "外盒需求": "一般紙盒", "標籤需求": "需要", "包裝其他需求": "" }
}
```

- `summary` 可以直接當 BKE A 表案件的 `summary`，例如：
  `BKECases.create({ type:'A', title: BKECases.suggestTitle(p.summary), customer: p.summary['客戶名稱'], applicant: '線上詢價', summary: p.summary, tasks: BKECases.tasksA(p.summary) })`
- 客戶勾「還不確定」的欄位存成 `尚未確認`，與 BKE 的寫法相同。
- A 表沒有的欄位（預計訂購量、外盒、標籤需求）放在 `extra`，同時寫進 `summary` 的 `成本備註`、`包材備註`，在 BKE 裡也看得到。

**報價（`oem-quote/1`，報價頁「複製 BKE 報價資料」）**

- `配方報價`：與 BKE `workflowData['配方報價']` 相同格式（初步配方號碼、原料成本、加工費、總計成本）。
- `對客報價`：報價單號、日期、方式、毛利率、三個方案的數量與單價、建議方案、包材規格。

## 設定寄信（Web3Forms）

1. 到 https://web3forms.com ，輸入業務要收信的 Email，取得 Access Key。
2. 打開 `index.html`，找到 `CONFIG`，把金鑰填進 `web3formsKey: ''`。
3. 推上 GitHub 後到網頁版送一筆測試詢價，確認收得到信。

金鑰留空時為示範模式：流程完整，送出後會標示「這次沒有真的寄出」，並列出業務會收到的 Email 內容。

## 報價計算

```
每盒成本 = 營養師配方成本（原料＋加工，換算每盒）× 損耗 + 內包材 + 外盒印刷 + 標籤與包裝工資 + 一次性費用 ÷ 訂購盒數
每盒報價 = 每盒成本 ÷ (1 − 目標毛利率)
建議方案 = 再加一級數量時，每盒若省不到 10% 就停在這一級
```

## 注意

- 包材、印刷、檢驗單價皆為課堂示範用估價，並非實際市場行情。
- 報價頁的計價參數寫在網頁裡，只適合內部使用；客戶詢價頁不含任何成本與價格。
- 本專案不修改 BKE；接進 BKE 的部分由 BKE 端處理。
